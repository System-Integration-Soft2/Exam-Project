## Quick answers

**What does a SOAP API consist of? Typical use cases?**  
A SOAP API sends XML messages wrapped in a standard **Envelope** (Header + Body) over HTTP POST to a single endpoint. The contract is defined in a **WSDL** file. Typical use cases: enterprise integrations, banking/finance, legacy system interop — where formal contracts, typed errors, and WS-* standards (security, transactions) matter more than simplicity.

**How is a SOAP API's syntax specified?**  
Via **WSDL** (*Web Services Description Language*) — an XML document that describes the service's operations, message formats, data types (XSD), protocol bindings, and endpoint address. In this project the WSDL is auto-generated by CoreWCF from the C# `[ServiceContract]`/`[DataContract]` attributes.

**How do SOAP APIs handle errors?**  
Via **SOAP Faults** — a standardised XML element inside `<Body>` containing `<faultcode>`, `<faultstring>`, and optional `<detail>` with typed fault data. This service uses `FaultException<NotFoundFault>` and `FaultException<ValidationFault>` to return structured error information. Unknown exceptions return a generic fault with no internal details (`IncludeExceptionDetailInFaults = false`).

**Advantages and disadvantages of SOAP?**  
Advantages: 
- formal contract (WSDL), typed faults, language-agnostic via XML, WS-* standards for security/transactions, secure (has built in error handling), reliable. 
 
Disadvantages: 
- verbose XML payloads, heavier than JSON/REST, harder to debug manually, steeper learning curve, overkill for simple CRUD APIs, very slow

## Explain how the WSDL file is created (show code)

**File:** `src/Program.cs` lines 25–38, `src/Contracts/IMovieService.cs`

The WSDL is **auto-generated by CoreWCF** from the C# contract. Three things make it happen:

```csharp
// Program.cs — 1. Register metadata services
builder.Services.AddServiceModelMetadata();
builder.Services.AddSingleton<IServiceBehavior, UseRequestHeadersForMetadataAddressBehavior>();
```

```csharp
// Program.cs — 2. Map the service to an endpoint with BasicHttpBinding
serviceBuilder.AddServiceEndpoint<MovieService, IMovieService>(
    new BasicHttpBinding(),
    "/movies.svc");
```

```csharp
// Program.cs — 3. Enable HTTP GET for the WSDL document
var serviceMetadataBehavior = app.Services.GetRequiredService<ServiceMetadataBehavior>();
serviceMetadataBehavior.HttpGetEnabled = true;
```

With these three pieces, CoreWCF inspects `IMovieService` and generates a WSDL at `http://localhost:8001/movies.svc?wsdl`. The `[ServiceContract]`, `[OperationContract]`, `[DataContract]`, `[DataMember]`, and `[FaultContract]` attributes on the C# code control exactly what appears in the WSDL.

## Explain the structure of the WSDL file

The WSDL at `/movies.svc?wsdl` has five main sections:

| Section | What it describes |
|---------|-------------------|
| `<types>` | XSD schemas for all data types — `MovieDto`, `CreateMovieRequest`, `NotFoundFault`, etc. Generated from `[DataContract]`/`[DataMember]` attributes. Field order comes from `[DataMember(Order = N)]`. |
| `<message>` | One message per operation input/output — e.g. `ListMoviesRequest`, `ListMoviesResponse`, `GetMovieByIdRequest`. Each references the XSD types defined above. |
| `<portType>` | The abstract interface — lists all 5 operations (`ListMovies`, `GetMovieById`, `CreateMovie`, `UpdateMovie`, `DeleteMovie`) with their input/output messages. Mirrors `IMovieService`. |
| `<binding>` | Concrete protocol details — specifies SOAP 1.1 over HTTP (`BasicHttpBinding`), `document/literal` style, and the `SOAPAction` header for each operation. |
| `<service>` | The endpoint address — `http://localhost:8001/movies.svc`. Where clients send their SOAP requests. |

The chain: **C# attributes → CoreWCF reflection → WSDL XML**. No hand-written WSDL needed.

## Explain how security is handled via faults (show code)

**Files:** `src/Contracts/IMovieService.cs`, `src/Services/MovieService.cs`, `src/Faults/`, `src/Validation/MovieValidator.cs`, `src/Program.cs`

SOAP doesn't use HTTP status codes for errors — it uses **typed faults** inside the SOAP envelope. This service has two fault types:

### Fault contracts declared on the interface

```csharp
// IMovieService.cs — each operation declares what faults it can throw
[OperationContract]
[FaultContract(typeof(NotFoundFault))]
MovieDto GetMovieById(GetMovieByIdRequest request);

[OperationContract]
[FaultContract(typeof(ValidationFault))]
[FaultContract(typeof(NotFoundFault))]
MovieDto UpdateMovie(UpdateMovieRequest request);
```

### Fault types

```csharp
// NotFoundFault.cs — returned when a movie ID doesn't exist
[DataContract]
public class NotFoundFault {
    [DataMember] public string Message { get; set; }
    [DataMember] public long MovieId { get; set; }
}

// ValidationFault.cs — returned when input fails validation
[DataContract]
public class ValidationFault {
    [DataMember] public string Message { get; set; }
    [DataMember] public string Code { get; set; } = "validation_error";
    [DataMember] public List<string> Errors { get; set; }   // list of specific issues
}
```

### Throwing faults in the service

```csharp
// MovieService.cs — GetMovieById
var movie = _repo.GetMovieById(request.Id);
if (movie is null)
    throw new FaultException<NotFoundFault>(
        new NotFoundFault { Message = $"Movie {request.Id} not found", MovieId = request.Id },
        new FaultReason($"Movie {request.Id} not found"));
```

```csharp
// MovieValidator.cs — validation throws ValidationFault
if (string.IsNullOrEmpty(title))
    throw new FaultException<ValidationFault>(
        new ValidationFault { Message = "title is required", Errors = ["title is required"] },
        new FaultReason("title is required"));
```

### Security: no internal details leaked

```csharp
// Program.cs — exception details are hidden from clients
serviceOptions.DebugBehavior.IncludeExceptionDetailInFaults = false;
```

This means: **known errors** return structured, typed fault data (safe). **Unknown exceptions** (bugs, crashes) return a generic SOAP fault with no stack trace or internal message. The client only sees what the fault contracts explicitly define.

### SQL-injection prevention

```csharp
// MovieRepository.cs — all queries use parameterised commands
cmd.CommandText = "SELECT ... FROM movies WHERE id = @id";
cmd.Parameters.AddWithValue("@id", id);
```

Never string concatenation — always `@parameter` placeholders via `SqliteCommand.Parameters`.

---

All messages are **XML SOAP envelopes over HTTP POST** to `/movies.svc`. The `SOAPAction` header identifies which operation to invoke. Faults are returned inside `<Fault><detail>` with the typed fault data.
